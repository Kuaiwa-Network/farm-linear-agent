# FarmBot 子任务职责与交接边界

状态：以下审计描述原版本；本次修订已实现工作规则收敛、版本化子任务边界、
认证源产物交接、父任务安装验收、scene 范围验证及安全前置修复交接。
本机验证与发布结果以发布维护目录中的实际记录为准；本文不表示已部署。

审计日期：2026-10-18。代码依据：`d7730fbea2395ea3d812b7962653f2546c395d48`。
本方案处理任务分工和证据交接，不授权恢复其他 issue、修改线上状态或跳过验收。

## 1. 当前到底有哪些子任务

调度器的 `CAPABILITIES` 只有 `fgui` 和 `scene`。只有顶层 `work`
可以创建它们，子任务不能再创建子任务。子任务共享父任务的 issue 工作树和分支，
但有独立的 claim、收件箱、检查点和进程；同仓库写入必须串行。

| 类型 | 当前执行者与职责 | 建议固定的边界 |
| --- | --- | --- |
| FGUI | 子任务；修改 farmgui、视觉确认、认证导出，并进入 Client 安装、处理导入元数据、检查依赖和 Unity 加载 | 负责指定 FGUI 包的源文件、预览、必要的视觉确认、认证导出及产物清单；交付到源资源就绪。Client 安装和验收移交主任务 |
| scene / Prefab | 子任务；修改 Client 场景、Prefab、展示资产及引用，做局部验证并交付 Client 草稿 | 负责指定 Unity 展示资产、它们的 `.meta` 与必要引用、局部验证；业务脚本和最终功能验收交给主任务 |
| 契约 A | 主任务在 Farm-Contract 的阶段 | 明确需求、验收标准、依赖和改动范围；已有要求足够时引用原有契约，避免无意义改文档或重新确认 |
| 配置 B/C | 主任务在 common 的阶段 | 修改必要的配置声明，验证实际配置是否就绪；策划数据决定仍由有权限的人负责 |
| 服务端 D | 主任务在 farm-hive 的阶段 | 实现相关业务和必要配套 CI 登记，按实际改动选择测试；仅需要服务时申请 server slot |
| 展示接入 E、客户端 F | 主任务在 Farm-Client 的阶段 | 消费展示产物，安装 FGUI，处理相关 `.meta`、依赖登记、业务代码和集成；运行候选验证及所需 QA |
| 收尾 G | 主任务 | 汇总有效证据、发布所需草稿 PR、报告遗留问题并完成 issue 交付；复用已有验收，不以交接为由再测一遍 |
| chat、feature、fix | 独立入口或兼容执行 profile；不是可委派的子任务 | chat 保持只读；feature/fix 保留各自既有权限。不能因为被称为“修复任务”就成为拥有任意权限的内部救援子任务 |
| 导出器、测试进程、资源调度 | 控制器及其受控工具；不是自主子 agent | 执行有明确输入和结果的操作，认证来源、管理租约和退出，不能自行扩大业务改动范围 |

QA 当前是主任务的验证活动，没有独立的持久 QA 子任务。换仓库、申请资源或恢复
执行时换了 worker 进程，也不等于新增了一个业务子任务。

## 2. 已确认的边界缺口

1. **FGUI 接管了 Client 安装。** `fgui` 的写权限包括 farmgui 和 Farm-Client，
   交付凭据要求完成安装、guards 和 Unity 加载。它当前遇到安装前置故障时，
   尚不能只交出已完成的源文件和认证导出，让主任务继续接入。
2. **主任务有修复责任，却可能没有接手机会。** `client_ready` 要求所有展示子任务
   delivered 且完成认证清理；`repository_busy` 在子任务进入 Client 后持续保留其
   写入所有权，包括等待和重试。协调阶段只允许协调，不能修 Client。
   因而“子任务等主任务修前置问题、主任务等子任务交付”会形成循环依赖。
3. **scene 的范围约束没有完整落实到交付校验。** 技能要求只修改指定展示资产，
   但 `scene_delivery` 当前核验的是授权、干净 HEAD、入口提交、草稿来源和零改动声明；
   它没有对有改动的交付核验具体资产范围或结构化局部测试结果。
   通用仓库保护仍存在；本结论不是发现了实际 worker 越界修改。
4. **任务依赖和范围主要藏在文字中。** 委派只接受 `key/capability/instructions`，
   没有结构化资产清单和依赖产物。FGUI 完成后才能创建依赖它的 scene，目前靠指令约定。
5. **安装前置检查把全仓旧问题混入当前任务。** FGUI 安装器的 GUID 清单读取扫描所有
   `Assets` 元数据，任一非法 GUID 就中止。FARM-1614 已观察到范围外既有元数据挡住
   安装；调整职责归属本身不会消除这个检查问题。

## 3. 子任务应该交什么

### FGUI：可消费的源资源产物

- 明确目标包、组件、允许的视觉变化、保留项及实际依赖；发现依赖变化先报告其原因，
  不把整个项目当成默认修改或导出范围。
- 提交指定源文件、预览和必要的真实人类确认。确认绑定源内容、包集合和预览，
  已确认且未变化的输入不因换进程或安装故障重新确认。
- 由现有受控导出器认证导出，记录源入口与结果提交、产物清单及摘要、工具身份、
  依赖和导出完成证据。退出与产物持久化经过控制器复核后，父任务才可以消费。
- 可以交付配置允许的 farmgui 源草稿 PR；Client 草稿与最终 issue 结果由主任务负责。
  子任务产物就绪不表示功能验收通过，也不表示 issue 已 finish。
- 内部 FGUI 子任务不再默认获得 Client 写权限或 Unity slot。主任务不能通过任意复制
  输出目录绕过认证安装，也不能把子任务旧的安装收据直接改成自己的收据。

### scene：指定 Unity 资产及其局部证明

- 目标是明确列出的场景、Prefab、展示资产以及必要引用；增删改文件需要可检查的范围。
  新依赖需要说明用途并经过范围校验，不能靠把整个 Assets 加进清单来过关。
- 可修改自己资产所需的 `.meta`，保留已有 GUID 身份；确实需要 Editor 制作或局部
  检查时可申请 Unity。不能笼统禁止 scene 使用 Unity 或接触任何 `.meta`。
- 交付入口提交、结果提交、资产差异、引用依赖和真实局部检查结果。
  不依赖主任务尚未实现的业务功能通过完整验收后，才允许交出资产。
- 涉及业务脚本、FGUI 重新导出或范围外修复时交回主任务协调。
  主任务消费资产后，负责最终 Client 草稿、业务验证和 issue 交付。
- 若所需 FGUI 资源尚未安装，scene 等待对应产物接入，期间不占 Client 写入权或 Editor。

### 主任务：集成和最终结果的唯一负责人

主任务决定任务是否需要拆分，绑定契约和验收标准，安排配置、服务端与展示工作，
消费产物并完成相关接入修复。重复使用同一候选已有的有效测试和 QA；只有诊断需要时
补充有针对性的基线比较，不能因为资源交接、旧失败或 main 前进就重开整轮验证。

最终质量要求不会因为把安装移到主任务而减少：相关安装安全、依赖检查、加载检查和
功能验收仍需成立。同一次候选验证若已经覆盖这些要求，就复用对应证据；原始失败仍
需保留和归因，不能把阶段改名当成测试通过。

## 4. 避免互相等待的交接协议

建议的依赖顺序如下；未涉及的步骤直接按实际范围省略：

```text
主任务确定契约和范围
  ├─ 主任务：配置／服务端
  └─ FGUI：指定包源文件 → 预览确认 → 认证导出 → 产物就绪并退出
       ↓
主任务：认证安装与必要前置修复
       ↓
scene：消费已安装资源 → 指定场景／Prefab 与局部检查 → 产物就绪并退出
       ↓
主任务：业务接入 → 候选验证及所需 QA → 证据汇总 → finish
```

独立的 scene 无需等待 FGUI；同一 Client 的写入仍然串行。
主任务需要独立的“接入／前置修复”阶段入口，不能继续用“所有子任务先完整交付”
作为任何 Client 写入的统一前提，也不能直接删除当前互斥保护。

跨边界阻塞使用明确的交接：

1. 记录具体阻塞、责任执行者、所需改动、已完成产物和依赖，区分工程修复、缺少真实
   人类决定、环境能力缺口和普通资源排队。
2. 保存子任务改动与证据，退休其 claim；确认所属进程和资源静默后才移交写入权。
   有未完成安装或未提交改动时先按恢复协议处理，不能假定工作树可直接接管。
3. 控制器向正确的执行者授予限定阶段权限；父子不同时写同一仓库。
   交接事件与真实人类答复使用不同通道，不能伪造 `answer-task` 消息来解锁工程动作。
4. 修复完成后检查产物依赖，只失效受影响的证据。保留原任务身份、原始入口和候选
   历史；确有修复提交时记录新候选及来源，不能悄悄重设到新 main。
5. 只有已履行约定交付条件并完成退出认证，才能标记该阶段完成。
   不创建替身子任务绕过旧任务锁，也不直接改数据库为 delivered。

## 5. 无关旧问题、权限与资源

全局 GUID 冲突和资源引用安全仍要检查。对于已有非法元数据，需证明它未被本次修改、
与安装目标及引用无关，并且不会让冲突判定失真，才可作为独立遗留问题记录。
新建／修改元数据必须合法。无法证明安全时，交给主任务执行可审核的必要前置修复，
而非让 FGUI 子任务扩散修改，也不能静默截断 GUID 或直接忽略扫描异常。

权限应落到控制器可验证的范围契约：指定仓库、入口、目标资产、允许操作、依赖产物
和验收要求。路径检查覆盖新增、删除、重命名、大小写别名、符号链接／junction 和
非预期脚本修改；配套 CI 登记只允许可证明必要的有限改动。执行环境仍保留仓库写根、
克隆配置保护、HOOKS_OFF、独立 claim、发布目标验证及进程归属检查。

Editor 只供实际制作或运行检查使用。等待人类、比较已有报告、检查发布信息和等待
依赖产物期间不保留空闲 Editor；任何释放与交接都以原有静默检查为条件。
后续必须执行的检查可在同一次候选预约内连续完成，不能仅因 worker 或阶段变化重复测试。

Monitor 应显示“谁在等谁、缺什么、下一步由谁执行”，例如：等待 GuildUI 认证导出、
主任务修复安装前置条件、等待视觉确认、等待 worker 名额或 Unity 内存条件。
任务内部等待不能显示成人类待答；源资源完成、安装完成、验证通过和 issue finish
需要分别表达。相同且未变化的阻塞不能反复唤醒父子 worker 空跑。

## 6. 落地顺序与验证要求

这些是后续实现项，不是已完成清单：

1. 定义版本化的任务范围、依赖和源产物收据；区分“产物就绪”和“集成通过”。
   控制器派生并复核归属和身份，worker 不能自报一个摘要就获得认证。
2. 增加内部 FGUI 源产物交付与父任务消费协议，调整 `dispatch`、skills、工作流、
   安装／交付验证和退出复核。兼容独立 FGUI profile，不能直接修改共享 manifest
   导致既有独立 UI 工作流失去安装能力。
3. 增加受控前置修复和写入权移交；修正 `client_ready` 的阶段条件、依赖检查、
   崩溃恢复和状态显示。移交机制先成立，再缩小 FGUI 权限。
4. 为 scene 增加资产范围与局部证据核验，明确是否需要 Editor；让最终 Client
   发布与功能验收集中于主任务。更新操作契约和 CLI 文档，使约束与实现一致。
5. 单独修正安装 GUID 诊断／归因和安全恢复，复用未变化的源、预览、导出证据，
   不把职责改造当成跳过安全检查的替代方案。

必要回归用例：

- FGUI 源完成、Client 安装失败时，主任务可在认证退出后接手，不需要子任务先完成安装；
  源与预览未变时不重复导出或请求视觉确认。
- 同仓库父子写入不重叠；进程未静默、旧租约、控制器重启、半完成安装都不误解锁。
- scene 的合法资产／必要 meta 可交付，越界脚本和未声明资产被拒绝；干净 PR 本身不能
  替代范围与实际检查证据。测试包含含空格及 Unicode 的路径。
- 依赖不存在、成环或未满足时拒绝错误启动；独立仓库工作仍可推进。
- 伪造／过期收据、错误父任务、源或候选改变、委派撤回都不能复用认证。
- 无关旧元数据、不完整冲突证据和真实目标 GUID 冲突分别得到正确结果；不降低安装安全。
- 父任务消费产物后，只做必要候选验证；已有同候选有效检查可复用，受影响的证据正确失效。
- 只向用户请求尚缺的人类决定；技术交接不会变成新一轮人类确认。

普通回归使用临时仓库、假 worker 和离线 fixture。涉及进程／资源交接的变化另外跑
原生 Windows 检查；不得把跳过项算通过。实现后按变更范围执行完整离线 CI。

## 7. 现有任务迁移

保留已有任务 generation、真实人类确认、源与候选历史、导出和安装日志。
旧的交付证明包含子任务身份和 Client 验证，不能改字段充当新的父任务消费证明。
新代码必须复核可复用的旧输入，签发版本明确的交接记录；无法安全转换的部分显式
走恢复流程。保留原始入口以审查累计改动，同时另记每次消费时的真实入口。

只有源导出的旧任务可在完成必要认证后移交；已经写入 Client 的任务还需先核对安装
日志、现有文件和退出状态。部署恢复需遵循维护交接，不手工释放仍在使用的资源。
若持久化结构变化，另行记录升级及恢复办法，不能假定回退代码就能回退数据库。

FARM-1614 可作为验收案例：复用已确认的 FGUI 源和认证导出，明确处理 Client 安装
前置缺陷，再做实际候选和功能验证。本方案本身尚未修复该缺陷，也不证明其已通过验收。
